# 出荷業務ツール集（表紙）  ver 2026-11-17

いろいろなツールの**入口をひとつ**にまとめる表紙です。
GitHub Pages に置くと、タブレットはURLひとつで全ツールを開けます。
一度開けば、**Wi-Fiがなくても動きます**。

## フォルダの中身

| ファイル | 役割 | ふだん直す？ |
|---|---|---|
| `tools.js` | エリア・つながり・ツール一覧と版（ver） | **ここだけ直す** |
| `index.html` | 表紙の画面 | 直さない |
| `sw.js` | オフライン保存のしくみ | 直さない |
| `manifest.json` / `icon-*.png` | ホーム画面に置くアイコン | 直さない |
| `tools/` | 各ツールのHTMLを入れる | ツールを入れ替える |

## 物と情報の流れ図の設定 ― `tools.js`

| 項目 | 中身 |
|---|---|
| `MAP_IMAGE` | 工場の図面画像（例：`map/factory.png`）。空欄なら方眼だけ |
| `AREAS` | エリアのボタン。`x, y, w, h` は横1000×縦600の方眼で位置と大きさを指定。`tools` にそのエリアのツールidを並べる |
| `LINKS` | エリア同士をつなぐ線。`mono`＝物の流れ（水色の実線、光が流れる）／`info`＝情報の流れ（紫の点線）。`bend` で曲がり具合 |

- 1つのツールを複数のエリアに置けます（例：かんばんカウンターはストアと出荷場）
- ツールが0個のエリアは点線の枠で「準備中」と表示されます
- `index.html#area=shukka` のようにURLを付けてホーム画面に登録すると、そのタブレットは開いた瞬間に出荷場のツールが出ます（タブレットごとの定位置）

## ツールを長押しで移動・コピー

1. 工程の中のツール（または一覧のツール）を **長押し**（PCは右クリック）
2. 「移動」か「コピー」を選び、置きたい工程を押す
   - 移動：元の工程から外して、選んだ工程へ
   - コピー：元の工程にも残したまま、選んだ工程にも置く
   - 「この工程から外す」：その工程からだけ外す
3. 変えた並びは **その端末だけ** に記録されます（画面上に水色の帯が出ます）
4. 全タブレットの標準にするときは、帯の「tools.js を書き出す」を押す
   → 並びと SITE_VER（今日の日付）が入った tools.js が保存されるので、GitHub の tools.js と差し替えて push
5. 「標準に戻す」で、tools.js の並びに戻ります

## GitHubの別リポジトリにあるツール（URLでつなぐ）

| ツール | 開く場所 |
|---|---|
| ポイント照合システム | `BASE + 'point-shogo/'` |
| 誤品照合 | `BASE + 'gohin/'` |
| 誤品照合システム（FTS） | `BASE + 'gihin2-FTS/'` |
| 掛け置き管理ツール | `BASE + 'naiji-kanri-tools/'` |
| 生産管理しくみ | `BASE + 'seisankanri-kakeoki-/'`（Publicにしてから） |
| 脱脂内示データ抽出 | `BASE + 'dasshi-naiji-HONDA-/'` |

- `BASE` は `https://overbridge038-lnk.github.io/`（`tools.js` の上のほう）
- **更新は連動します**：各リポジトリに push すると、そのツールが新しい版になります
- **ver も自動**：表紙は Wi-Fi につながったとき（開いたとき・30分ごと・「最新か確認」）に、各ツールの画面の ver を読み取って表示し、変わっていれば「更新」バッジを出します。`tools.js` の ver を手で直す必要はありません
- 各リポジトリで **Settings → Pages を有効** にしておくこと
- 「保存済み／未保存」は、そのツール自身がオフライン保存しているかを表示します

### オフライン保存がないツールに足す（offline-kit）
掛け置き管理ツール・脱脂内示データ抽出・生産管理しくみ には 2026-11-17 に入れました（同じ方法で、これから増えるツールにも足せます）。
※ 保存の名前はツールごとに分けること（同じ github.io の中で保存場所を共有しているため。消すのは自分の古い保存だけにする）。
1. `offline-kit/sw.js` を、そのリポジトリのツールと同じフォルダに置く
2. ツールのHTML（脱脂は `脱脂内示データ抽出.html`）の `</body>` の前に次の1行を入れる
   `<script>if('serviceWorker' in navigator)navigator.serviceWorker.register('sw.js');</script>`
3. push する
- ネット優先なので、Wi-Fi があれば必ず最新版、なければ最後に開いた版で動きます（ver の上げ忘れも起きません）

## はじめの準備

1. GitHubで新しいリポジトリを作る（例：`shukka-tools`）
2. このフォルダの中身をすべてアップロード
3. 各ツールのHTMLを `tools/` に入れる
4. `tools.js` の `file:` を実際のファイル名に合わせる
5. リポジトリの Settings → Pages で `main` ブランチを選んで保存
6. 表示されたURLをタブレットのChromeで開き、
   メニューの「ホーム画面に追加」を押す

## ツールを直したときの更新（3ステップ）

1. ツール本体を直し、画面の ver を今日の日付にする
2. `tools.js` で、そのツールの `ver` と `SITE_VER` を今日の日付にする
3. GitHub に push する

→ タブレットがWi-Fiにつながると、新しい版を裏で取り込みます。
→ 表紙に黄色い帯「新しい版があります」が出るので、「更新する」を押せば切り替わります。
→ 直したツールには「更新 11/20」のようなバッジが付きます。

**SITE_VER を上げ忘れると、タブレットに届きません。** ここだけ注意してください。

## TPSの考え方

- **入口をひとつに（標準化）**：どのタブレットも同じURL、同じ表紙
- **配る作業をなくす（ムダの排除・自働化）**：1台ずつコピーして回らない
- **物と情報の流れを見える化**：マップ上で物（実線）と情報（点線）の流れをつなぎ、どこで何のツールを使うかを一目で
- **版を一目で（目で見る管理）**：表紙とツールの ver、更新バッジ、保存済み表示
- **標準は1つ（標準作業）**：長押しでの変更はまず端末だけで試し、よければ書き出して全タブレットの標準にする（改善→標準化）
- **あんどん**：新しい版が届いたら黄色い帯で知らせる。作業中の画面を勝手に切り替えず、区切りのよいときに人が押す

## 注意

- ファイルをダブルクリックして開く（`file://`）と、オフライン保存は動きません。GitHub Pages（https）で開いてください
- CDNのライブラリ（Excel読み書きなど）を使うツールは、一度Wi-Fiにつないだ状態で開いておくと、オフラインでも使えるようになります
- Publicリポジトリには図面や金額（単価・売上など）を載せないこと。実データは現場でCSVなどを読み込む形にします
- 各ツールの上に `tools/_sample-tool.html` の「← 表紙へ」の帯を入れておくと、表紙へ戻りやすくなります
